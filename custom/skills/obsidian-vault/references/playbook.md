# Obsidian Vault Playbook

An evolving list of conventions for `/home/skynguyen/Documents/Obsidian Vault/`.
Each bullet has a stable ID, a category tag, and helpful/harmful counters.
Edit individual bullets in place — do not rewrite this file wholesale.

Format: `[ID] [category] statement — helpful:N harmful:N`

---

- [B001] [naming] Use Title Case for all note filenames — helpful:0 harmful:0
- [B002] [structure] Vault is flat — no folders for organization; use links and index notes instead — helpful:0 harmful:0
- [B003] [linking] Use Obsidian `[[wikilinks]]` syntax (`[[Note Title]]`) for all cross-references — helpful:0 harmful:0
- [B004] [linking] Each note links to its dependencies/related notes in a section at the bottom — helpful:0 harmful:0
- [B005] [index] Index notes aggregate related topics (e.g. `Skills Index.md`) and consist purely of `[[wikilinks]]` lists — helpful:0 harmful:0
- [B006] [content] Write note content as a self-contained unit of learning, not a fragment — helpful:0 harmful:0
- [B007] [numbering] If a note is part of a sequence, use a hierarchical numbering scheme (e.g. `1`, `1.1`, `1.2`) in the title or frontmatter — helpful:0 harmful:0
- [B008] [safety] Before creating a note, verify no same-named file already exists — this is a mutating operation and must not silently overwrite — helpful:0 harmful:0
- [B009] [content] New notes use the frontmatter + section templates in `references/templates.md` (type, status, tags, created/updated); pick "Regular note" or "Index note" — helpful:0 harmful:0
- [B010] [content] Notes carry a `status` lifecycle (`seed` → `growing` → `evergreen`); bump `updated` and move status forward on edits rather than resetting it — helpful:0 harmful:0
